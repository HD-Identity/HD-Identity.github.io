# WSL 2 中配置代理服务器教程

> 适用于 WSL 2 环境下需要通过 Windows 宿主机代理访问外网的场景（例如安装 Claude Code、npm 包、curl 外网等）。

## 前置条件

1. **WSL 2 已安装并正常运行**（可通过 `wsl -l -v` 确认版本为 2）
2. **Windows 宿主机上的代理客户端已运行**，例如：
   - v2rayN
   - Clash for Windows / Clash Verge
   - Shadowsocks 客户端
3. **代理客户端已开启“允许来自局域网的连接”**（Allow LAN），并记下 **HTTP 代理端口**（常见值：Clash 默认 `7890`，v2rayN 默认 `10808`）

---

## 方法一：NAT 模式（使用宿主机 IP）

**特点**：适用于 WSL 默认网络模式（NAT），配置简单，但宿主机 IP 可能随网络变化而改变。

### 步骤

1. **获取 Windows 宿主机的 IP 地址**  
   在 WSL 终端中执行：
   ```bash
   cat /etc/resolv.conf | grep nameserver | awk '{print $2}'
   ```
   输出示例：`172.29.176.1`（这个 IP 就是 Windows 在 WSL 虚拟网络中的地址）。

2. **设置代理环境变量**  
   将上一步得到的 IP 和你的代理端口（例如 `10808`）填入：
   ```bash
   export host_ip=$(cat /etc/resolv.conf | grep nameserver | awk '{print $2}')
   export http_proxy="http://${host_ip}:10808"
   export https_proxy="http://${host_ip}:10808"
   export all_proxy="socks5://${host_ip}:10808"   # 如果代理支持 SOCKS5
   ```

3. **测试连通性**  
   ```bash
   curl -I https://www.google.com
   ```
   若返回 `HTTP/2 200` 或 `301`，说明代理配置成功。

4. **永久生效（可选）**  
   将上述 `export` 命令添加到 `~/.bashrc` 或 `~/.zshrc` 中：
   ```bash
   echo '# WSL 代理配置 (NAT 模式)' >> ~/.bashrc
   echo 'export host_ip=$(cat /etc/resolv.conf | grep nameserver | awk '{print $2}')' >> ~/.bashrc
   echo 'export http_proxy="http://${host_ip}:10808"' >> ~/.bashrc
   echo 'export https_proxy="http://${host_ip}:10808"' >> ~/.bashrc
   echo 'export all_proxy="socks5://${host_ip}:10808"' >> ~/.bashrc
   source ~/.bashrc
   ```

### 注意事项

- 每次 WSL 重启或网络变更后，`/etc/resolv.conf` 中的 IP 可能变化，建议每次登录时重新获取（上述永久配置已解决）。
- 如果代理端口不是 `10808`，请相应修改。
- 使用 `sudo` 执行命令时，环境变量不会继承。可用 `sudo -E` 保留当前环境变量，或在 root 下重新设置。

## 方法二：镜像模式（使用 127.0.0.1）

**特点**：让 WSL 与 Windows 共享网络栈，可以直接使用 `127.0.0.1` 访问宿主机服务。配置稍复杂，但一劳永逸，且无需关心 IP 变化。

### 要求
- **Windows 11 22H2 及以上** 版本
- **WSL 2.0.0 及以上**版本（可通过 `wsl --version` 查看）
- 如版本不满足，请运行 `wsl --update` 升级。

### 步骤

1. **编辑 `.wslconfig` 文件**  
   在 Windows 用户目录（`C:\Users\你的用户名\`）下创建或编辑 `.wslconfig`，添加以下内容：
   ```ini
   [wsl2]
   networkingMode=mirrored
   dnsTunneling=true
   firewall=true
   autoProxy=true
   ```

2. **重启 WSL**  
   以管理员身份打开 PowerShell 或 CMD，执行：
   ```powershell
   wsl --shutdown
   ```
   然后重新打开 WSL 终端。

3. **设置代理环境变量**（现在可直接使用 `127.0.0.1`）
   ```bash
   export http_proxy="http://127.0.0.1:10808"
   export https_proxy="http://127.0.0.1:10808"
   export all_proxy="socks5://127.0.0.1:10808"
   ```

4. **测试连通性**
   ```bash
   curl -I https://www.google.com
   ```

5. **永久生效**
   ```bash
   echo '# WSL 代理配置 (镜像模式)' >> ~/.bashrc
   echo 'export http_proxy="http://127.0.0.1:10808"' >> ~/.bashrc
   echo 'export https_proxy="http://127.0.0.1:10808"' >> ~/.bashrc
   echo 'export all_proxy="socks5://127.0.0.1:10808"' >> ~/.bashrc
   source ~/.bashrc
   ```

### 常见问题与解决

#### ❌ `curl: (7) Failed to connect to 127.0.0.1 port 10808: Connection refused`
**原因**：
- 代理客户端未监听 `0.0.0.0`（只监听了 `127.0.0.1`）。
- Windows 防火墙拦截了来自 WSL 的入站连接。

**解决方法**：
1. **修改代理客户端监听地址**：在 v2rayN / Clash 中勾选 **“允许来自局域网的连接”**，并将监听地址改为 `0.0.0.0`（或留空）。
2. **添加防火墙规则**：以管理员身份运行 PowerShell，执行：
   ```powershell
   New-NetFirewallRule -DisplayName "Allow Proxy for WSL" -Direction Inbound -LocalPort 10808 -Protocol TCP -Action Allow
   ```
3. **临时关闭防火墙测试**（用于快速定位）。

#### ❌ 镜像模式设置后网络反而异常？
- 检查 `.wslconfig` 中 `firewall=true` 是否与某些 VPN 冲突；可尝试暂时设为 `false`。
- 更新 WSL 至最新版：`wsl --update`。

#### ❌ 代理设置后 `ping` 不通外网？
`ping` 使用 ICMP 协议，不通过代理，这是正常的。请用 `curl` 测试。

## 验证与常用命令

- **查看当前代理环境变量**：`env | grep -i proxy`
- **取消代理（临时）**：`unset http_proxy https_proxy all_proxy`
- **测试代理是否工作**：`curl -I https://www.google.com` 或 `curl ip.sb`

## 总结

| 方法                     | 优点                  | 缺点                                  | 适用场景               |
| :----------------------- | :-------------------- | :------------------------------------ | :--------------------- |
| **NAT + 宿主机 IP**      | 配置简单，兼容性好    | IP 可能变化，需动态获取               | WSL 默认配置，快速使用 |
| **镜像模式 + 127.0.0.1** | 稳定，IP 固定，体验好 | 需要 Windows 11 + WSL 2.0，配置略复杂 | 长期使用，推荐配置     |

根据你的 Windows 版本和需求选择一种方法即可。如果镜像模式遇到问题，可以回退到 NAT 模式。
